# 战斗与同步契约

下表按玩法事件描述职责和数据。当前项目的可靠入口为 `event(sequence, code, bytes)`，第二个参数 `code` 取自 `channel.gd` 的 `Code` 枚举，用来区分攻击、命中、提交、回执等事件，第三个参数 `bytes` 承载事件字段。移动输入另走 `input_sample`。查找实际方法、参数和编码时以[通道实现](../../../horde-survivors-3d/net/channel.gd)为准。底层使用 Godot 原生 Shared 节点、Spawner 和可靠 RPC。SDK 已提供动态生成、等待写权基线、指定玩家 RPC 及房主收权入口。玩法层负责命中、去重、批处理和经验结算。[原生接入说明](../../../../netcode/docs/specs/godot-scene-sync.md) · [对象授权与恢复](../../../../netcode/docs/specs/object-authority.md)

## 对象边界

| 对象 | 权威字段 | 写入端 |
|---|---|---|
| PlayerMotion | 玩家 ID、XZ 坐标、朝向、速度、模拟步 | A 为房主，B/C 为该玩家。A 的客机上传带序号的移动输入 |
| PlayerCombat | 玩家 ID、HP、无敌截止步、倒地标记、生命状态版本 | 三档均为该玩家。接触、冲锋、Boss 圈按本地呈现的危险区域和自己的位置判定。按攻击实例与伤害段去重，受击立即更新本地血量 |
| Enemy | 怪物 ID、负责人、授权代次、XZ 坐标、朝向、追击目标、HP、状态版本、存活标记 | 当前负责人。B 档全部归房主；C 档按批预分配，单只怪保持独立身份 |
| RunState | 局 ID、种子、阶段、截止步、团队经验、等级、待选升级、已确认构筑、胜负 | 房主。一次生成一个局内唯一 ID，死亡和掉落记录在对象移除后仍可核对 |

镜头、骨骼姿势、刀光、伤害飘字、经验吸附轨迹均由各端绘制。队友动作从公开的姿态、速度和起手事件还原。攻击碰撞和可见的命中范围共用 XZ 几何定义。

怪物由本端模拟时直接呈现本端位置。远端副本在每帧向最新快照插值，时长按到达间隔调整为 32–100 ms，超过时长后保持在最后收到的位置。换权、出生和大跨度位置变化重置插值。飞刀、圣环、落雷与本地接触共用呈现坐标，掉落位置和结算仍取持权状态。

## 消息与结算

所有业务请求带局 ID。对象使用本局内唯一整数 ID，攻次和状态版本为单调递增整数，时刻采用同一局的模拟步，XZ 和方向采用两分量向量。接收方用实际连接身份核对发送玩家。T3 基准使用 60 Hz 玩法模拟和默认 30 ms SDK 网络步；远端实际收到的怪物更新间隔按每场记录，见[阶段测量](../验收/T3.md)。

| 消息 | 必需字段 | 投递、结果与重复处理 |
|---|---|---|
| AttackStart | 玩家、攻次、武器、起始步、起点 XZ、方向、构筑版本、表现种子 | 本人先播，观察端按攻次播放一次。飞刀重建轨迹，圣环按节拍取样，落雷按确认命中清单绘制远端连锁 |
| HitBatch | 玩家、攻次、武器、构筑版本、命中步、目标清单；每项含怪物 ID、伤害段、当时的授权代次 | 攻击者决定目标，同一步命中按负责人分批。收件人检查身份、已生效构筑、目标和重复项，按武器表取伤害。返回逐项结果及怪物状态版本；过时代次按当前负责人重投原业务键 |
| EnemyCommit | 怪物 ID、代次、前后状态版本、本批新增命中键、结果 HP、死亡标记 | 负责人把一次结算作为整体交房主记录。房主仅按版本衔接接纳一次，再确认攻击者和发布死亡掉落。重复批返回已有结果；遇版本缺口先补齐 |
| DangerStart | 危险实例 ID、来源、形状与 XZ 参数、预警起始步、生效步、结束步、伤害段 | Boss 由房主发布，冲锋由怪物负责人发布。玩家本机判断是否命中，写 PlayerCombat。迟到且已经结束的预警只消除残留表现，不追扣血；记录迟到计数 |
| PickupClaim → PickupResult | 掉落 ID、玩家、请求序号 → 是否领取、获领玩家、团队经验版本 | 先播放吸附，房主按掉落 ID 接受第一个有效请求。重试返回同一结果。经验总量从 RunState 收敛 |
| ChooseUpgrade → UpgradeResult | 玩家、升级轮次、选项 ID → 接纳结果、构筑版本、生效步 | 房主每人每轮接纳一个选项，重试返回已选结果。其他玩家和房间时钟继续推进 |

命中业务键取（局、攻击玩家、攻次、怪物、伤害段），在换权时保持稳定。两人的攻次可同为 1；飞刀对同怪只记一段，圣环下一次合法脉冲使用新段。50 血的怪同时收到 12 和 18 两笔伤害，双方最后看到 20 血。已经消耗的业务键再送一次，血量仍为 20。致死转换只产生一条死亡记录，掉落 ID 从该死亡记录派生。正式结果返回时按业务键合并已有本地飘字和闪白。

## 换权与断线

房主在刷怪时记下预定负责人，授权基线到齐并且 `is_write_ready()` 后新端开始写。实施时先验证“客机申请、房主批准、客机可写”的原生路径。房主记录每只怪最近已接纳的结算版本、命中去重记录及死亡派生结果。去重记录至少保留到该攻次的全部在途重试结束，首个六分钟版本可保留至局末并记录内存峰值。

普通怪负责人掉线，房主从最后接纳的坐标、目标和战斗记录收回怪群。仍在房间的攻击者对未获最终确认的命中重送原业务键；已记账的直接回复，未记账的由新负责人结算。旧代次的迟到提交不能产生新死亡或掉落。首版房主离开时返回大厅；房主迁移属于后续扩展。

## 实现参数

玩家移动、玩家受击与普通怪分别使用独立 Shared 模板。玩法固定 60 Hz，Windows 原生 TCP SDK 操作步为 30 ms，未修改 SDK 的默认时基。C 档房主在出生时选择预定负责人，客机通过 Transaction 申请，写权基线可用后才推进模拟。房主收到断线事件时封闭旧业务代，从原生复制基线接管位置，再用已接纳账本覆盖血量与结算版本。

命中先到房主，房主按当前负责人拆批后投递。负责人可连续计算同一目标的新版本，房主按业务键与前后版本提交。最终回执按实际批量装入有序可靠消息，每个目标仍有独立结果。短时原生拒绝由应用发送队列重试，游戏逻辑重试保留原业务键。空屋/退房释放本局队列。局内保留死亡、掉落与命中去重历史。[实现](../../../horde-survivors-3d/combat/battle.gd) · [原生 RPC 适配](../../../horde-survivors-3d/net/channel.gd)
