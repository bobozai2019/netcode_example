# 双人玩法和同步性能验证方案

本文规定待执行的试验。实施后在本目录新增阶段结果，附入口、命令、构建、机器、复现参数、预期与实测；原始逐帧数据放示例仓的 `out/`。可参考[已有双端负载验证脚本](../../../tools/verify_sync_lab.py)和[已有 Godot 分项测量](../../../../netcode/task/godot-platform/验收/T5.md)。

GitHub 仓库包含测试方案、汇总和复跑命令。各报告中的 `out/` 链接指向本地测试归档，克隆后可运行对应命令生成自己的记录。

## 正确性用例

| ID | 操作 | 通过条件 |
|---|---|---|
| V1 双人同击 | 50 血的怪分别受到 12、18 伤害；重投其中一条。另让圣环下一脉冲再击中它 | 两端先收敛到 20 血，重投无额外伤害，下一次合法脉冲使 HP 再下降。飘字按实际攻次和段数显示 |
| V2 自己判定受击 | 让主机和客机分别在预警圈生效前移出、留在圈内、在无敌期内再次接触。测试局域网及 100 ms RTT | 每位玩家本机出圈时免伤、留圈时掉血一次，无敌期内不再扣血；另一端最终看到相同玩家 HP。记录预警到达时剩余的反应时间 |
| V3 同杀同抢 | 两人同时补刀，随后在同一时间窗拾取同一经验石 | 同一怪物只有一条死亡记录、一份对应掉落。两端共享经验恰好增加该经验石面值；下一次升级每人只能确认一个选项 |
| V4 交接与旧消息 | 房主攻击客机负责的怪，分别在致命结算接纳前、接纳后让客机掉线。在房主接管后重投该命中并送入旧代结果 | 接管从最近接纳的状态恢复，原攻击恰好结算一次，怪物不会复活，死亡与掉落均为一份，房主可继续移动和攻击 |
| V5 三档隔离 | 回放相同输入，记录房主/客机负责对象数与战斗判定端。在 B、C 档做分路、会合、交叉攻击 | 观察到 A/B/C 三种预定归属，所有模式均由攻击者判定命中、本人判定受击。C 会合后的写权保持稳定，两端结束时存活数、Boss HP、团队经验相同 |
| V6 完整对局 | 三种武器分别升级一次；一人选升级时另一人继续走位；分别触发击败 Boss、全员倒地和超时 | 预警圈、技能范围与 XZ 判定吻合，队友保持操作；两端升级结果和局末胜负一致，每局只结算一次 |

T1 用飞刀验证 V1 的同击与重投，用练习圈验证 V2，执行 V3 的同杀与拾取。T2 的 V5 先核对普通怪存活数、逐怪 HP 和团队经验。T3 加入圣环、升级和 Boss 后，补测 V1 的多段伤害、V2 的正式预警、V3 的升级和 V5 的 Boss HP，再走 V6。

## 对照方法

1. 记录两台机器的 CPU/GPU、分辨率、渲染设置、帧率限制、Godot 与实际加载的 SDK 构建号。优先用两台机器跑有画面的客户端并交换主客角色；同机双进程结果单列。同一组保持种子、输入回放、构筑、模拟与发送频率、可见性策略和显示质量一致。
2. 在 128 只怪下先测 A/B/C，分别在局域网和实测约 100 ms 的**总往返时间**下走完分路、合流、同时爆发。再按 256、512、1024 逐级提高密度。记录每端实际存活、实际可见、实际负责的怪物数及每秒有效命中数；对比时使用负载相近的窗口。
3. 建议每档预热 10 秒，采集至少 30 秒稳态窗口，重复三次。A/B/C 顺序轮换，按端、场景、重复轮次列值。容量档先用有画面的完整场景，遇到长帧时以相同回放切到简化网格、关闭骨骼和特效复测；必要时加测无窗口逻辑耗时。

| 指标 | 取样方法与判读 |
|---|---|
| 本地即时反馈 | 同进程单调时钟记录输入采样、首个显示位移帧、起手/命中反馈帧；位移与起手单列。60 FPS 下首轮目标为 B/C 两端本地反馈 P95 ≤ 33 ms，主客 P95 差 ≤ 1 帧。这里度量应用侧提交显示帧的时间 |
| 正式确认延迟 | 同一攻击者上，从本地判定命中到收到最终回执，按本端负责、跨端负责单列 P50/P95；另记拒绝、重复和待确认数量 |
| 帧耗时与状态年龄 | 主客分别报 P50/P95/P99 帧耗时，分列渲染、骨骼动画、AI、碰撞、复制采样和消息处理的可用计时。状态年龄按房间时钟对齐到来源步并记录时钟误差；同一时钟不可用时单列快照到达间隔 |
| 线量与路由 | 分别记录上下行字节/秒、每秒 RPC、每批命中目标数、每端负责对象数和是否有积压。注明字节采集在传输层还是应用载荷层 |
| 结算与容量 | 停止刷怪与攻击，待已发命中完成后比较两端存活数、Boss HP、团队经验；重复伤害、重复死亡、重复奖励应为 0。以双端 P95 帧耗时 ≤ 20 ms、本地反馈达标、确认队列无持续增长且对账通过时的最高实测档，作为 B/C 首轮可玩容量 |

阶段报告至少给出两项比较：从 A 换到 B，客机移动反馈改善多少；从 B 换到 C，房主节省多少模拟时间，客机新增多少计算与上行，密集交叉攻击时确认延迟增加多少。上表时延和帧耗时均为拟定验收目标，硬件、场景和网络条件随结果一同报告。
