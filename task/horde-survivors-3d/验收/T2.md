# T2 多授权验收

2026-11-25 使用 Godot 4.6.1 stable `14d19694e`、原生 SDK `929c4f1663907b23/cbd0dce8d269280e`。同机两个进程通过 TCP 房间传输。C 档的怪物由客机先请求 Transaction 写权，房主批准，客机读取基线后确认可写。

```powershell
python -B benchmark/run.py --cases before after --modes C --label handoff-repeat
python -B benchmark/run.py --skip-prepare --cases win --modes A B C --label boss-repeat
```

| 断线点 | 断线前房主账面 HP | 接管后 HP | 有效命中 / 死亡 / 掉落 | 旧代拒绝 |
| --- | ---: | ---: | --- | ---: |
| 客机提交获准前 | 12 | 0 | 1 / 1 / 1 | 1 |
| 客机提交获准后 | 0 | 0 | 1 / 1 / 1 | 1 |

断线由另一个进程实际退出触发，旧代提交由验证器注入房主校验入口。两条重放均通过，主机继续移动，重复业务键未新增伤害、死亡或掉落。已死亡对象也推进账本授权代次，避免晚到的提交影响掉落。

A/B/C 的 Boss 用例都收敛到 0 HP、1 次死亡和胜利，双方构筑一致。容量回放分端记录角色移动写权、普通怪写权、写权基线等待、应用消息积压、确认时间和实际 TCP 流字节。首组逐档数值见 [T3 性能表](T3.md)。
