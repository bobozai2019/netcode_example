# T1 双人原型验收

2026-11-25 在同一台 Windows x64 机器运行两个独立 Godot 进程。实际加载 Godot 4.6.1 stable `14d19694e`、原生 SDK `929c4f1663907b23/cbd0dce8d269280e`。测试用真实 TCP 房间和原生 Spawner。可玩窗口复用带 Idle、Run、HitReact 和 Death 的士兵，角色各有一套本地正交镜头。[工程与启动](../../../horde-survivors-3d/README.md) · [模型来源与许可](../../../horde-survivors-3d/assets/sources.json)

在示例工程目录执行以下命令。

```powershell
python -B benchmark/run.py --cases rules --delay 0 40 64 --label t1-repeat
```

| 附加 RTT | 客机实测 RTT P50 | 客机预警到达时的剩余反应时间 P50 | V1–V3 |
| ---: | ---: | ---: | --- |
| 0 ms | 50.0 ms | 1066.7 ms | 通过 |
| 40 ms | 104.1 ms | 1033.3 ms | 通过 |
| 64 ms | 129.1 ms | 1033.3 ms | 通过 |

- V1 的 50 HP 练习怪分别承受 12 和 18 伤害，两端均显示 20 HP。重复投递保持 20 HP，圣环下一段使 HP 降到 2。最后双方同时补刀，全局仅记一次死亡。
- V2 让房主与客机分别出圈并留圈。房主最终 87 HP，客机 83 HP。双方在无敌期内的第二次预警均未扣血，两端看到同一组 HP。
- V3 双方在同一窗口重复拾取面值 8 的死亡掉落，团队经验从 8 到 16，经验版本从 1 到 2。死亡、掉落和团队经验收敛，双方随后均看到 128 只活怪。

测试以脚本输入复现移动、争抢、危险区域和升级，V1 使用指定目标注入两笔可核对伤害。正常玩法由可见几何生成命中。记录的移动反馈是应用侧帧提交时间，带画面的对照在 T3。
